## [todo/kinopoisk_api.py] — 178 строк | оценка 5/10

### Функции:
- `_api_base_url` (~строка 10) — читает `KINOPOISK_API_URL` из env при каждом вызове
- `_api_headers` (~строка 14) — собирает заголовок `X-API-KEY`
- `kinopoisk_get` (~строка 18) — единственная точка HTTP-запроса, `timeout=30`
- `search_films` (~строка 28) — поиск по ключевому слову, маппинг в список карточек
- `fetch_film_details` (~строка 63) — детали фильма (v2.2)
- `fetch_film_staff` (~строка 70) — съёмочная группа (v1)
- `fetch_film_distributions` (~строка 77) — прокатные даты (v2.2)
- `fetch_film_external_sources` (~строка 84) — платформы просмотра (v2.2)
- `premiere_dates_from_distributions` (~строка 94) — выбор мировой и российской премьеры
- `watchability_from_external_sources` (~строка 115) — маппинг платформ в `{name, url}`
- `parse_age_rating` (~строка 122) — вытаскивает цифры из `ratingAgeLimits`
- `format_person_name` (~строка 130) — «Имя RU / Имя EN»
- `staff_by_profession` (~строка 136) — фильтр персон по `professionKey` с лимитом
- `build_film_detail` (~строка 144) — агрегирует 4 запроса в один словарь детали

### Проблемы:
- [КРИТИЧНО] Сетевые ошибки не обрабатываются: `requests.get` (~строка 19) может выбросить `ConnectionError`/`Timeout`/`SSLError` — исключение уходит наружу в вью и превращается в 500. base.md требует `raise SpecificError("context") from err`, здесь нет ни одного своего исключения.
- [КРИТИЧНО] `json.loads(response.content)` вызывается без защиты в 5 местах (~строки 36, 67, 73, 81, 91): при HTTP 200 с HTML/пустым телом (типично для заглушек и капчи прокси) получаем неперехваченный `JSONDecodeError`.
- [КРИТИЧНО] Ошибки внешнего API молча проглатываются: при статусе ≠200 `fetch_film_staff` возвращает `[]` (~строка 73), `fetch_film_distributions`/`fetch_film_external_sources` — `{}` (~строки 80, 90). Ответ 401 (истёк токен) или 429 (rate limit) выглядит как «у фильма нет актёров и премьер», и в БД записывается пустота. Логирования в модуле нет вообще — диагностировать невозможно (нарушение base.md про structured logging).
- [КРИТИЧНО] Полиморфный контракт возврата: `search_films` возвращает `list` при успехе и `dict {'message': ...}` при ошибке (~строки 34, 60); `fetch_film_details` — детали или тот же «словарь-ошибку». Вызывающий код обязан делать `isinstance`-проверки, а `build_film_detail` определяет ошибку по наличию ключа `'message'` (~строка 146) — если API однажды вернёт поле `message`, валидный фильм будет принят за ошибку.
- [ВАЖНО] `build_film_detail` делает 4 последовательных синхронных HTTP-запроса внутри цикла запроса-ответа Django: при деградации Kinopoisk один клик = до 120 с ожидания (4 × timeout 30). Кэширование отсутствует, хотя Redis заявлен в стеке base.md.
- [ВАЖНО] Дублирование: четыре `fetch_*` функции повторяют один и тот же шаблон «запрос → проверка 200 → `json.loads`», отличаясь только путём и значением-заглушкой. Нужен один хелпер декодирования.
- [ВАЖНО] Нет `response.raise_for_status()`, нет retry/backoff — у Kinopoisk API жёсткие лимиты запросов, 429 не обрабатывается.
- [ВАЖНО] Ни одной аннотации типов в модуле, ни одного docstring; контракты словарей нигде не описаны.
- [МЕЛКО] `search_films(keyword, limit)` принимает `limit` строкой и делает `int(limit)` внутри (~строка 38) — протекающий контракт: приведение типа из env лежит на слое API-клиента.
- [МЕЛКО] Магические числа в коде: 15 актёров и 5 режиссёров (~строки 154-155), `timeout=30`, `page: 1`.
- [МЕЛКО] Версии API (`v1`, `v2.1`, `v2.2`) захардкожены в строках путей — нет константы/конфига.
- [МЕЛКО] `NO_POSTER` (~строка 7) ссылается на сторонний хост `i.ibb.co` — внешняя зависимость в рантайме.

### Функции:

- `get_preview_content` (~строка 18) — достаёт `title` из POST и лимит из env, вызывает поиск
- `get_detail_film` (~строка 28) — тонкая обёртка над `build_film_detail`
- `IndexView.get` / `IndexView.get_context` (~строки 35, 38) — главная страница со списком заметок и формой
- `PreView.post` (~строка 49) — результаты поиска либо страница ошибки
- `DetailView.get` (~строка 59) — карточка заметки по `note_id`
- `SaveView.get` (~строка 66) — создаёт/обновляет `Movie` и `Note`
- `DeleteView.post` (~строка 99) — удаляет заметку

### Проблемы:
- [КРИТИЧНО] `SaveView.get` (~строка 66) изменяет состояние БД через GET-запрос: `Movie.objects.update_or_create` + `Note.objects.update_or_create`. GET обязан быть идемпотентным — любой краулер, префетч браузера или `<img src>` создаёт записи, и CSRF-защита Django на GET не действует. Должен быть POST.
- [КРИТИЧНО] `get_object_or_404(User, pk=1)` (~строка 67) — владелец заметки захардкожен как пользователь с pk=1. Все заметки принадлежат одному аккаунту, а если суперюзер из миграции `0002` не создан или получил другой pk — сохранение отдаёт 404 без объяснения.
- [КРИТИЧНО] `get_note_list` (~строка 9) возвращает `Note.objects.all()` без фильтра по `request.user` — на главной каждый видит заметки всех пользователей. Плюс `except Note.DoesNotExist` (~строка 12) — мёртвая ветка: queryset такого исключения не выбрасывает, то есть обработка ошибки существует только на бумаге.
- [КРИТИЧНО] `DetailView.get` (~строка 60) и `DeleteView.post` (~строка 100) достают `Note` по pk без проверки владельца — классический IDOR: подставив чужой `note_id`, можно прочитать и удалить чужую заметку. Во всём приложении нет ни `LoginRequiredMixin`, ни проверок прав.
- [КРИТИЧНО] Страница ошибки отдаётся с HTTP 200: `render(request, 'todo/error.html', content)` (~строки 52, 70) при недоступном Kinopoisk API. Мониторинг и клиенты считают такой ответ успешным; корректный код — 502/503.
- [ВАЖНО] `get_note_list(self)` (~строка 9) — модульная функция с параметром `self`, вызывается как `get_note_list(self)` из метода вью (~строка 39). Аргумент не используется, сигнатура вводит в заблуждение.
- [ВАЖНО] `SaveView.get` содержит 22-строчный литерал `defaults={...}` (~строки 71-92) — маппинг API-ответа на поля модели живёт во вью. Слоя `services/` нет вообще, хотя base.md задаёт для него порог покрытия 80%.
- [ВАЖНО] Локальный импорт `from envjson import env_str` внутри `get_preview_content` (~строка 19) — скрытая зависимость. Значение `MAX_COUNT_MOVIE_PER_REQUEST` читается на каждый запрос и не валидируется: нечисловое значение даёт `ValueError` из `int(limit)` уже в API-клиенте.
- [ВАЖНО] Логирования нет: ни одного вызова `logger`, при ошибке внешнего API в логах не остаётся следа.
- [ВАЖНО] N+1 запросов: `Note.objects.all()` без `select_related('movie')`, при этом шаблон `index.html` в цикле обращается к `item.movie.*`.
- [МЕЛКО] Закомментированный `SeenView` на 6 строк в конце файла (~строки 105-110) плюс парная закомментированная строка в `todo/urls.py` — технический долг.
- [МЕЛКО] `if note:` (~строка 101) после `get_object_or_404` — условие всегда истинно.
- [МЕЛКО] Классы наследуют `TemplateView`, но переопределяют `get`/`post` и вызывают `render` вручную, игнорируя `get_context_data`/`template_name` — идиомы Django не используются, объявленный `template_name` не задействован.

## [todo/templatetags/todo_extras.py] — 62 строки | оценка 7/10

### Функции:
- `_format_person` (~строка 8) — приводит строку или «legacy»-словарь `{имя_ru: имя_en}` к строке
- `format_person_list` (~строка 25) — фильтр: список персон через запятую
- `format_watchability` (~строка 33) — фильтр: список платформ в виде HTML-ссылок
- `format_rating` (~строка 52) — фильтр: рейтинг с одним знаком после запятой, без `.0`

### Проблемы:
- [КРИТИЧНО] `format_watchability` (~строки 44-48) вставляет `url` в атрибут `href` и оборачивает результат в `mark_safe`. `escape()` защищает от выхода из атрибута, но схема URL не валидируется: значение вида `javascript:...`, пришедшее из внешнего API и сохранённое в `Movie.watchability`, станет исполняемой ссылкой (хранимый XSS). Нужна проверка на `http`/`https`.
- [ВАЖНО] Ручная сборка HTML в Python вместо inclusion-шаблона: любое изменение разметки требует правки кода и повторной проверки экранирования — в шаблоне это было бы безопасно по умолчанию.

### Проблемы:
- [ВАЖНО] Четыре независимых блока вместо одного (~строки 74-77): каждый дочерний шаблон обязан «угадать» свой блок (`{% block preview %}`, `{% block detail %}`, `{% block error %}`), иначе страница отрендерится пустой. Один `{% block content %}` решил бы задачу без этой хрупкой договорённости.

- [ВАЖНО] Пункты навигации «Watch today» и «Seen» ведут на `#` (~строки 68-69) — нерабочее меню в основном layout; парная незавершённость с закомментированным `SeenView` во `views.py`.

- [ВАЖНО] Все 24 CSS/JS-ресурса берутся из `static/todo/lib/**/dist/**` (~строки 38-52, 94-107). При этом nginx-конфиг не отдаёт `/static/`, а `dist/` попадает под исключения сборки — в проде страница останется без стилей и скриптов.
- [МЕЛКО] Год в footer захардкожен «2023» (~строка 83) — устаревает сам по себе.
- [МЕЛКО] Подключаются библиотеки, не используемые на страницах проекта (`jquery.mb.YTPlayer`, `flexslider`, `simple-text-rotator`, `wow`) — лишний вес на каждой загрузке.
